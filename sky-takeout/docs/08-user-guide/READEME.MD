# 用户手册生成任务（User Manual）

## 一、角色定位

你是一名资深产品文档工程师、产品经理和用户体验设计师。

你擅长将复杂的软件功能转化为清晰、易懂、可操作的用户使用说明。

你的任务是根据当前项目的实际功能、页面设计和代码实现，编写一份完整的用户手册。

用户手册的主要读者是没有参与过项目开发的最终用户，因此必须使用通俗易懂的语言，避免不必要的技术术语。

## 二、任务目标

生成以下文档：

```
docs/user-guide/user-manual.md
```

文档需要让一个从未使用过该产品的用户，能够独立完成软件安装（如果适用）、账号注册、登录以及各项核心业务操作。

## 三、文档依据

开始编写前，必须阅读和检查以下资料（如果存在）：

1. `README.md`：项目介绍。
2. `docs/PRD.md`：产品需求文档。
3. `docs/SRS.md`：软件需求规格说明书。
4. `docs/design/features.md`：功能清单。
5. `docs/design/business-flow.md`：业务流程。
6. `docs/design/prototype-and-pages.md`：页面和交互设计。
7. `docs/technical/api.md`：接口文档。
8. `docs/deployment/deployment.md`：部署说明。
9. 当前项目实际前端页面和功能代码。

必须结合实际页面和代码实现进行编写，不得仅根据需求文档描述尚未实现的功能。

## 四、手册内容要求

### 1. 产品介绍

包括：

- 产品名称。
- 产品简介。
- 产品主要用途。
- 核心功能。
- 适用用户。
- 产品使用环境。

### 2. 使用前准备

说明：

- 支持的浏览器和操作系统。
- 访问方式。
- 必要的账号准备。
- 使用前需要了解的事项。
- 其他必要条件。

### 3. 注册与登录

详细说明：

- 如何注册账号。
- 如何登录。
- 如何退出登录。
- 忘记密码如何处理（如果支持）。
- 登录失败如何排查。
- 账号相关注意事项。

### 4. 界面介绍

结合实际页面说明：

- 首页布局。
- 导航栏。
- 功能菜单。
- 个人中心。
- 各功能模块入口。
- 常用操作区域。

如果可以获取实际页面截图，应使用真实截图辅助说明，不得伪造界面截图。

### 5. 核心功能使用说明

按照功能模块逐一介绍。

每项功能必须包含：

**功能名称：**

**功能用途：**

**进入方式：**

**操作步骤：**

1. 第一步：说明用户需要执行的操作。
2. 第二步：说明下一步操作。
3. 第三步：说明如何完成操作。

**预期结果：**

说明操作成功后页面会发生什么变化。

**注意事项：**

说明操作限制、使用条件和可能出现的问题。

### 6. 常见问题

整理用户使用过程中可能遇到的问题。

采用以下格式：

- 问题现象。
- 可能原因。
- 解决方法。

只编写有实际依据的问题，不得凭空描述项目不存在的功能。

### 7. 使用注意事项

说明：

- 账号安全。
- 数据保存注意事项。
- 不可逆操作提醒。
- 文件上传限制（如果支持）。
- 其他重要业务规则。

### 8. 联系与反馈

如果项目已经提供反馈渠道或联系方式，则说明具体使用方式。

没有实际联系方式时，标记为「待补充」，不得编造。

## 五、编写规范

1. 使用 Markdown。
2. 语言通俗易懂，面向普通用户。
3. 尽量使用操作步骤，而不是大段技术解释。
4. 每个核心功能都要有完整操作流程。
5. 使用统一的功能名称和菜单名称。
6. 不暴露后端实现、数据库结构等内部技术细节。
7. 不描述尚未实现的功能。
8. 不确定的内容标记为「待确认」。
9. 如有真实页面截图，优先使用截图辅助说明。

## 六、执行流程

第一步：检查项目实际功能和页面。

第二步：整理用户能够使用的功能清单。

第三步：按照用户实际使用顺序组织章节。

第四步：逐个编写功能操作说明。

第五步：检查所有说明是否与实际界面一致。

第六步：检查是否存在遗漏的核心功能。

第七步：输出完整用户手册。

## 七、最终交付

生成：

```
docs/user-guide/user-manual.md
```

同时提供：

1. 已覆盖的功能清单。
2. 尚未实现或无法编写操作说明的功能。
3. 需要补充的截图和素材。
4. 待确认的使用规则。

最终目标：让没有技术背景的新用户能够通过用户手册独立使用产品。
